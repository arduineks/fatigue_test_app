# task.md — Видение проекта и план внедрения нового функционала

## Видение

Приложение — рабочее место оператора установки усталостных испытаний материалов
протезов клапанов сердца (полимеры SIBS/PVA/PU, биоматериал-перикард; образцы
dog-bone ISO 37 Type 4). Цель — провести испытание **по стандартным протоколам
усталости полимеров** (ISO 13003, ASTM D5992, ISO 6943) и получить на выходе
данные для кривых усталости (S-N / ε-N / W-N), пригодные в том числе для
калибровки моделей повреждаемости (CDM) в Abaqus.

### Ключевое ограничение (принято)

**Замкнутого управления амплитудой и частотой нагружения нет.** Аппаратура,
задающая амплитуду и частоту, не имеет обратной связи с приложением: оператор
настраивает режим на стенде вручную и периодически проверяет/подстраивает его.

Отсюда роль приложения:

- **Монитор и анализатор**: считать циклы, следить за MAX/MIN/MID/амплитудой,
  жёсткостью, ползучестью, разогревом — и **сигнализировать оператору**, когда
  режим уплыл или приближается к критерию отказа.
- **Ассистент подстройки**: показывать отклонение фактической амплитуды/частоты
  от заданных оператором целей и подсказывать, когда пора подстроить
  (drift-индикаторы + алерты, без автоматических команд к стенду).
- **Протоколист**: вести поцикловую запись, классифицировать исход
  (run-out / отказ / прерван) и формировать отчёт по образцу и серии.

Поддержание среднего уровня силы регулятором (существующий функционал через
MOVE траверсы) сохраняется как есть. Ничего из нового плана не требует
изменений прошивки, кроме опционального канала температуры (отдельный пункт).

Существующий регулятор держит среднюю силу (MID) — это и есть управление
средним уровнем; амплитуду оператор задаёт на стенде. Приложение только
контролирует соответствие факта заданным целям.

## Зависимости и риски

- **Частота нагружения**: поток кадров 20–25 Гц — детектор циклов надёжно
  работает до ~1–2 Гц нагружения; выше — вопросы к прошивке, не к приложению.
- **Согласование force+mm**: петля гистерезиса имеет смысл только при
  синхронной по времени записи обоих каналов из одного кадра (в кадре
  `<BiiffB` оба есть) — не смешивать с разными буферами.
- **Детектор пиков**: любые изменения (1.6) проверять симуляцией на
  `logs/app_debug.log` (прогон FSM старый/новый, сравнение с огибающей).
- **UI**: новые карточки/поля добавляются рядом с существующими, не вместо
  (правило «не удалять UI без вопроса»); всё внутри в Н, МПа — слой отображения.
- **Обновление карточек**: только из таймера `update_measurement_info` (100 мс),
  не из serial-пути.
