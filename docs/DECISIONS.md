# Принятые решения (ADR)

Формат: краткое решение, контекст, последствия. Новые решения добавляются сверху.

## ADR-001 — Модульный сплит main.py (2026-10-06)

**Решение.** Разбить монолит `main.py` (~5155 строк) на модули:
`protocol.py` (константы протокола), `graph_widget.py` (`ForceGraphWidget`),
`calibration_window.py` (`CalibrationWindow`), `main.py` — тонкая точка входа.

**Контекст.** Единственный файл был основным барьером для тестов и параллельной
работы. Требование пользователя — инкрементальность: не ломать работающее поведение.

**Последствия.**
- Тела классов перенесены без изменений (проверено побайтовым сравнением), поведение не менялось.
- Импорты: `calibration_window` импортирует константы из `protocol` и `ForceGraphWidget`
  из `graph_widget`; `main.py` ре-экспортирует оба класса.
- Мёртвый код (`add_value`, `create_line_style_combo`) перенесён как есть — удаляется
  отдельной задачей (беклог №9), чтобы сплит оставался чисто механическим.
- Дальнейшее дробление (cycle_analyzer, data_buffer, SerialManager) — отдельные шаги,
  см. беклог №1, №7.

## ADR-002 — Документация проекта ведётся в docs/ (2026-10-06)

**Решение.** Беклог, принятые решения, техдолг и известные баги ведутся в
`docs/BACKLOG.md`, `docs/DECISIONS.md`, `docs/TECH_DEBT.md`, `docs/BUGS.md`;
README ссылается на них, а не дублирует.

**Контекст.** Обязательное правило пользователя: поддерживать документацию о беклоге,
решениях, техдолге и багах. Ранее список ограничений жил только в README и устаревал.

**Последствия.** При каждом изменении архитектуры — новый ADR; найденные баги —
в BUGS.md с шагами воспроизведения; планы — в BACKLOG.md с приоритетами.

## ADR-005 — Интерактивный режим и цветовая унификация (2026-10-06)

**Решения.**
1. Тумблер «Интерактивный режим» в шапке окна (рядом с подключением). Включён:
   изменение поля ввода (Enter / потеря фокуса — `editingFinished`) применяет его
   сразу: «Целевая точка траверсы» → MOVE, «Целевая сила» → новая цель регулятора,
   скорость → для следующего перемещения. Кнопки остаются рабочими как дублирование.
2. Перед полями добавлены подписи: «Целевая точка траверсы, мм», «Скорость траверсы,
   мм/с», «Целевая сила, Н».
3. При активном «поддержании силы» блок «Положение траверсы» переводится в read-only
   (поля readonly, кнопка ПЕРЕМЕСТИТЬ disabled, заголовок блока помечается) —
   регулятор сам управляет траверсой; при остановке блок возвращается пользователю.
4. Цветовая унификация (2026-10-06, уточнено пользователем): шаблон карточек циклов —
   окно «ТЕКУЩЕЕ ЗНАЧЕНИЕ» (фон #08151A, рамка #1C7F90, radius 5); значение — цветом
   линии соответствующего показателя (раньше цветом была подпись), подпись — серая
   #8B9AA5 как у «ТЕКУЩЕЕ ЗНАЧЕНИЕ». При смене цвета линии на графике фон окна
   (не текст) подсвечивается цветом линии (rgba 60/255): СРЕДНЕЕ ← MID, МИН СИЛА ← MIN,
   МАКС СИЛА ← MAX (колбэки on_mid/on_min/on_max_color_changed).
5. «Интерактивный режим» — тумблер с бегунком (кастомный ToggleSwitch на QCheckBox:
   капсула 44×24, круглый бегунок, подсветка при включении), не чекбокс-заливка.

**Причина.** Запрос пользователя; фикс AttributeError `on_interactive_field_changed`
(сигналы были подключены в прерванной сессии без обработчика — BUG-5).

## ADR-004 — Амплитуда вместо дельты, регулятор силы (2026-10-06)

**Решения.**
1. Белая линия = mid последнего цикла (`cycle_mid = cycle_mid_value`), как было
   изначально (вариант с усреднением по 5 циклам был отменён пользователем).
2. Карточка «ДЕЛЬТА» заменена на «АМПЛИТУДА» = (max − min) / 2 (полуамплитуда цикла);
   карточка «СРЕДНЕЕ» = (min + max) / 2 сохранена (соответствует белой линии).
3. Регулятор поддержания силы на главном экране: поля «таргетная сила» и «скорость»,
   галочка «Автоматическое вычисление скорости», кнопка «НАЧАТЬ ПОДДЕРЖИВАТЬ».
   Решение — по среднему силы за скользящее окно 4 с (`MAINTAIN_WINDOW_S`), не по
   мгновенному значению. При попадании среднего в полосу ±0.05 Н — «цель поймана»:
   MOVE в текущую позицию (остановка) и полное прекращение подстроек, пока среднее
   снова не выйдет из допуска. Вне допуска: шаг пропорционален ошибке (0.02–0.2 мм),
   cooldown = шаг/скорость + 0.3 с (без него MOVE копились в очереди MCU — траверса
   дёргалась верх-низ). Авто-скорость: мм/с = ошибка(Н) × MAINTAIN_AUTO_SPEED_GAIN,
   кламп 0.0–5.0 (при 0 — движения нет). Направление «подъём увеличивает силу»
   — `MAINTAIN_UP_INCREASES_FORCE`.

**Контекст.** Запрос пользователя под усталостные испытания: стабильная средняя линия
при дрейфе циклов, амплитуда как стандартный параметр нагружения, удержание заданной
силы перед/во время испытания.

**Последствия.** Параметры регулятора (допуск, шаг, такт) — константы класса, не UI;
требуют подбора на стенде. Регулятор без проверки достижения конца хода — при
упоре в границу хода будет слать MOVE без результата (требует проверки на стенде).
Прошивка STM32 имеет команду TARGETN (целевая сила на стороне MCU) — если окажется,
что MCU сам держит силу, регулятор на ПК можно заменить на START + TARGETN.
Команды MOVE шлются с 6 знаками после запятой: минимальный ход за такт
(0.005 мм/с × 0.2 с × 1.5 = 0.0015 мм) меньше 0.001 мм-кванта формата .3f —
округление давало ±33% ошибки хода за такт и дрожание у цели (2026-10-06).
Если прошивка парсит MOVE фиксированной точностью 3 знака — вернуть .3f.

## ADR-006 — Единицы силы Н/МПа (2026-10-06)

**Решение.** Внутри системы сила всегда хранится в Н (протокол с STM32 не меняется).
Отображение переключается дропдауном Н/МПа:
- Блок «ПАРАМЕТРЫ ОБРАЗЦА» перед «УСИЛИЕ»: ширина и толщина (мм) → площадь
  сечения (мм²), пересчитывается на `editingFinished`.
- Дропдаун в блоке «УСИЛИЕ» управляет графиком и карточками: у `ForceGraphWidget`
  добавлены `display_units`/`area_mm2`/`to_display()` — конверсия только при отрисовке
  (значения кривой, шкала Y с суффиксом, линии MAX/MID/MIN).
- Дропдаун у целевой силы поддержания: значение поля в МПа конвертируется в Н
  (`value × площадь`) перед передачей регулятору; без площади — ошибка в лог.
- Карточки МИН/МАКС/СРЕДНЕЕ/АМПЛИТУДА и текущая сила — через
  `convert_force_value()`/`current_force_suffix()`.
- RAW и FILTERED остаются в отсчётах АЦП, единицы не меняют.

**Причина.** Усталостные испытания оперируют напряжением (МПа), а датчик меряет силу.

**Последствия.** МПа недоступен, пока не заданы ширина и толщина (>0) — суффикс
остаётся «N». При смене единиц карточки пересчитываются сразу; график — при
следующей перерисовке (масштаб Y пересчитывается от max в новых единицах).

## ADR-003 — Верификация без запуска GUI (2026-10-06)

**Решение.** Проверка рефакторинга: `py_compile` всех модулей + побайтовое сравнение
перенесённых тел классов с оригиналом (`git show HEAD:main.py`).

**Контекст.** PyQt5 не установлен ни в одном окружении машины (приложение
собирали/запускали на другой машине), запуск GUI невозможен без установки пакетов,
которые по правилам не ставятся без подтверждения пользователя.

**Последствия.** До первого запуска на машине с PyQt5 нет smoke-теста instantiate окон;
после установки зависимостей прогнать `QT_QPA_PLATFORM=offscreen` -тест instantiate
(см. BUGS.md/BACKLOG). Побайтовое сравнение компенсирует отсутствие запуска.
