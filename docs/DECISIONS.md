# Принятые решения (ADR)

Формат: краткое решение, контекст, последствия. Новые решения добавляются сверху.

## ADR-001 — Модульный сплит main.py (2026-10-06)

**Решение.** Разбить монолит `main.py` (~5155 строк) на модули:
`protocol.py` (константы протокола), `graph_widget.py` (`ForceGraphWidget`),
`calibration_window.py` (`CalibrationWindow`), `main.py` — тонкая точка входа.

**Контекст.** Единственный файл был основным барьером для тестов и параллельной
работы. Требование пользователя — инкрементальность: не ломать работающее поведение.

**Последствия.**
- Тела классов перенесены без изменений (проверено побайтовым сравнением), поведение не менялось.
- Импорты: `calibration_window` импортирует константы из `protocol` и `ForceGraphWidget`
  из `graph_widget`; `main.py` ре-экспортирует оба класса.
- Мёртвый код (`add_value`, `create_line_style_combo`) перенесён как есть — удаляется
  отдельной задачей (беклог №9), чтобы сплит оставался чисто механическим.
- Дальнейшее дробление (cycle_analyzer, data_buffer, SerialManager) — отдельные шаги,
  см. беклог №1, №7.

## ADR-002 — Документация проекта ведётся в docs/ (2026-10-06)

**Решение.** Беклог, принятые решения, техдолг и известные баги ведутся в
`docs/BACKLOG.md`, `docs/DECISIONS.md`, `docs/TECH_DEBT.md`, `docs/BUGS.md`;
README ссылается на них, а не дублирует.

**Контекст.** Обязательное правило пользователя: поддерживать документацию о беклоге,
решениях, техдолге и багах. Ранее список ограничений жил только в README и устаревал.

**Последствия.** При каждом изменении архитектуры — новый ADR; найденные баги —
в BUGS.md с шагами воспроизведения; планы — в BACKLOG.md с приоритетами.

## ADR-003 — Верификация без запуска GUI (2026-10-06)

**Решение.** Проверка рефакторинга: `py_compile` всех модулей + побайтовое сравнение
перенесённых тел классов с оригиналом (`git show HEAD:main.py`).

**Контекст.** PyQt5 не установлен ни в одном окружении машины (приложение
собирали/запускали на другой машине), запуск GUI невозможен без установки пакетов,
которые по правилам не ставятся без подтверждения пользователя.

**Последствия.** До первого запуска на машине с PyQt5 нет smoke-теста instantiate окон;
после установки зависимостей прогнать `QT_QPA_PLATFORM=offscreen` -тест instantiate
(см. BUGS.md/BACKLOG). Побайтовое сравнение компенсирует отсутствие запуска.
